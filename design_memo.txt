A stack is the right choice for an undo and redo system because it follows the Last In, First Out (LIFO) rule. The most recent action is the first action that needs to be undone. In my program, when a user performs an action, it is pushed onto the undo stack. When the user chooses undo, the most recent action is popped from the undo stack and pushed onto the redo stack. If the user performs a new action after undoing something, the redo stack is cleared because the previous redo actions are no longer part of the current sequence.

A queue is better suited for a help desk because customers should be helped in the same order that they arrive. This follows the First In, First Out (FIFO) rule. My queue keeps track of both the front and rear nodes. New customers are added to the rear, while customers are removed from the front. This makes sure the first customer who joins the line is the first customer helped.

My implementations differ from Python’s built-in lists because I created the data structures myself using Node objects and pointers. A Python list has built-in methods for adding, removing, and accessing items, while my Stack and Queue classes control how data can be accessed. The Stack only works from the top, and the Queue manages data from the front and rear. Building these structures myself helped me understand how stacks and queues work internally.
